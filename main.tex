    \subsection*{Propuesta de solución}
    El objetivo del código es implementar un sistema de lectura de datos a través del puerto serie (USB) de manera no bloqueante. Tradicionalmente, funciones como \texttt{input()} detienen por completo la ejecución del procesador hasta que el usuario ingresa un dato. Para evitar esto, se propone el uso del módulo \texttt{select}, el cual permite sondear (\textit{polling}) el búfer de entrada estándar (\texttt{sys.stdin})  . El programa registra este flujo de entrada y, mediante un ciclo infinito, verifica si hay algún byte esperando ser leído en el búfer sin detener el procesador  . Si se detecta información, se extrae exactamente un carácter y se imprime un mensaje de confirmación  .

     El flujo de datos de este código inicia con la importación de las bibliotecas necesarias para monitorear el flujo de entrada en la consola. Se registra la entrada estándar y se manda a imprimir un mensaje indicando que se está esperando un carácter. Posteriormente, el programa entra en un bucle infinito que constantemente comprueba la función \texttt{poll(0)}. Si llega alguna información desde Thonny al microcontrolador a través del USB, el condicional se activa, lee exactamente un dato e imprime inmediatamente un respectivo "Hola UNAM". Independientemente de si detecta datos o no, se realiza una pausa de 100 milisegundos al final de cada iteración para que el procesador no se sature.

    \subsection*{Propuesta de solución}
    Esta actividad combina la lectura no bloqueante del puerto serie con el control directo de las salidas digitales del microcontrolador . Se configura el pin físico \texttt{GPIO25} (conectado al LED integrado de la Raspberry Pi Pico) como una salida digital (\texttt{Pin.OUT}) . Replicando la estructura de sondeo con el módulo \texttt{select}, el programa extrae los caracteres entrantes desde la consola de Thonny .

    El control se realiza mediante una estructura condicional \texttt{if-elif} . El carácter recuperado por \texttt{sys.stdin.read(1)} se compara contra los caracteres ASCII de control definidos en la tabla . Si el programa recibe el carácter \texttt{'1'}, saturará el pin a nivel alto ; si recibe \texttt{'0'}, drenará el voltaje a nivel bajo . Cualquier otro carácter (como letras o el retorno de carro enviado al presionar Enter) será simplemente ignorado por el flujo condicional, evitando falsas activaciones.

Tras efectuar las comprobaciones de los posibles escenarios o de no haberse escrito absolutamente nada en consola, detiene por 0.1 segundos el procedimiento de barrido principal y todo vuelve a empezar.

    \subsection*{Propuesta de solución}

    Para poder implementar la tabla de control de la actividad 6, es necesario configurar la comunicación UART a través del módulo Bluetooth. Debido a que se va requerir controlar los pines GPIO es necesario impotar los modulos \texttt{Pin} y \texttt{UART} de la librería \texttt{machine}. 

    Una vez importados los módulos, se configura la comunicación UART a través del módulo Bluetooth, para esto por medio de la función \texttt{UART} se establece la velocidad de comunicación \textit{baudrate} a 9600 baudios, se asignan los pines de transmisión y recepción (TX = \texttt{PIN 16} y RX = \texttt{PIN 17}).

    Posteriormente, se configuran los pines GPIO0 a GPIO3 como salidas digitales (\texttt{Pin.OUT}) para controlar los LEDs que se encuentran conectados a estos pines.

    Posteriormente a declarar los pines, se procede a implementar un bucle infinito el cual constantemente monitorea el buffer de recepción del puerto serie, utilizando la función \texttt{uart.any()} para verificar si hay datos disponibles. Si se recibe un comando, se lee el primmer carácter del buffer con \texttt{uart.read(1)}, se convierte los bytes recibidos a una cadena de texto usando \texttt{decode('utf-8')} además por medio del método \texttt{upper()} se asegura que el comando se interprete correctamente sin importar si el usuario lo ingresa en mayúscula o minúscula.

    Al obtener el comando recibido, por medio de una estructura condicional \texttt{if-elif} se identifica que acción se debe ejecutar, dependiendo del comando se asignan los valores necesarios a los pines para lograr el encendido o apagado deseado.

    \section*{Propuesta de solución}

    Para implementar el control de los motores de corriente directa de acuerdo a los comandos recibidos por Bluetooth, es necesario en el programa importar la librería \texttt{machine} donde se usaran los módulos de salida \texttt{Pin} para controlar los pines GPIO y el módulo \texttt{UART} para el protocolo de comunicación serial.

    Una vez importadas las librerías, es necesario configurar la comunicación \texttt{UART} a través del módulo Bluetooth, para esto por medio de la función \texttt{UART} se establece la velocidad de comunicación \textit{baudrate} a 9600 baudios, se asignan los pines de transmisión y recepción (TX = \texttt{PIN 16} y RX = \texttt{PIN 17}).

    Posteriormente, se configuran los pines de los motores, dado que el control de los motores se realiza por medio de un puente H, se necesitan 3 pines para controlar el motor, 2 pines para la dirección del giro y un pin para apagar o encender el motor. Para el primer motor se usan los pines \texttt{GPIO0}, \texttt{GPIO1} y \texttt{GPIO20}, mientras que para el segundo motor se usan los pines \texttt{GPIO2}, \texttt{GPIO3} y \texttt{GPIO19}. Es importante destacar que todos los pines se configuran como salidas digitales (\texttt{Pin.OUT}).

    Para una mejor organización del código, se define una función auxiliar llamada \texttt{control\_motor} la cuál realiza dos acciones principales, la primeara es elegir que pines usar según el número que recibe como argumento y la segunda es ejecutar la acción correspondiente al comando recibido, para esto se hace uso de una estructura condicional \texttt{if-elif} que compara el comando recibido con los caracteres definidos en la tabla de control, dependiendo del comando se asignan los valores necesarios a los pines para lograr el giro deseado o detener el motor.

    Antes de entrar al bucle principal, se inicializa en estado de apago ambos motores, para esto se asigna un valor de 0 a los pines de control de ambos motores, esto con la finalidad de evitar que los motores se activen de manera inesperada al iniciar el programa.

    Se implementa un bucle infinito el cual constantemente monitorea el buffer de recepción del puerto serie, utilizando la función \texttt{uart.any()} para verificar si hay datos disponibles. Si se recibe un comando, se lee el primmer carácter del buffer con \texttt{uart.read(1)}, se convierte los bytes recibidos a una cadena de texto usando \texttt{decode('utf-8')} además por medio del método \texttt{upper()} se asegura que el comando se interprete correctamente sin importar si el usuario lo ingresa en mayúscula o minúscula. 
    De acuerdo al valor del comando recibido  por medio de una estructura condicional \texttt{if-elif} se identifica que acción se debe ejecutar, para esto se llama a la función \texttt{control\_motor} pasando como argumentos el número del motor a controlar y el comando recibido.
